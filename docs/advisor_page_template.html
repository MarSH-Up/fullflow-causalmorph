Hardening the nsDCBN pipeline: what changed, and what the numbers say now

A re-audit of the extraction pipeline found three defects that shaped every structure number reported in October: an adjacency convention mismatch that scored reversed edges as correct, a consensus rule that returned the complete graph for half the grid, and a post-processing rule that deleted most detected change points at large p. This page shows the pipeline before and after on the same 600 scenarios, under the corrected scoring.

The detector was never the weak part it looked like. Its reported recall of 0.48 was mostly a post-processing rule (max(250, 10p²)) that deleted every change point next to a regime shorter than that bound — from p = 8 upward, all of them. With that rule replaced and a new change statistic (v1L), recall is {{DET_R_AFTER}} at precision {{DET_P_AFTER}}, flat across the position of the change point in the series.

The structure numbers were measured against the transpose of the truth. lingam returns B[to, from]; the generator and every metric use A[from, to]; nothing converted between them. The oracle-seeded pipeline produced reversed graphs that the reversed metric scored as correct, and the prior-free baselines produced correct graphs that it scored as failures. Under the corrected scoring, the plain per-window learners beat the pipeline's extraction layer, and the configuration that won in October (bootstrap at 0.60, window overlap 0.15, oracle seed, consensus at 0.20) loses on every metric to a cold start with none of those.

1 · Change-point detection

{{TABLE_DETECTION}}

Why the old statistic decayed with position

v1H thresholded the Frobenius norm of the correlation change over all m = p(p−1)/2 pairs, calibrated once on regime 0. A sparse change in 3 of 66 pairs is diluted by the estimation noise of the other 63, and the generator makes the first transition carry about twice the edge changes of later ones, so later change points sat below a threshold set on the first. v1L standardises each pair on the Fisher scale, divides by its own robust null scale (the Gaussian variance is 1.2–1.7× too small on this grid and grows with p), takes the maximum over pairs, and thresholds analytically. Precision is flat across p.

2 · The adjacency convention

Three layouts were in play and nothing converted between them:

Measured on grid scenarios, recall of window 0 scored as-is / scored on the transpose: oracle-seeded pipeline 1.00 / 0.00, cold start 0.00 / 1.00, cold start with its prior transposed 1.00 / 0.00. The cold pipeline produced the correct graph and was scored as a complete reversal. The oracle path handed CausalMorph the truth in [from, to], which it read as the reversed graph; because its transform imposes the prior's orientation, DirectLiNGAM returned the reversed graph, which the reversed metric then scored as correct. Two errors cancelling for the seeded pipeline, compounding for the baselines.

What the October tables measured: the pipeline's ability to recover the reverse of the true DAG, seeded with the reverse of the true prior. The 99.4% / 99.99% win-rates against DirectLiNGAM and ICA-LiNGAM invert under the corrected scoring: the baselines win.

The fix is one convention inside the pipeline, A[from, to], with explicit converters at the two library boundaries, pinned by tests on a V1 → V2 → V3 SEM where every learner now scores recall ≥ 0.5 against the truth (each was 0.0 with SHD 4: both edges missing, both reversals present).

4 · What each piece is worth

{{TABLE_SWEEP}}

Window overlap prepends 15% of the previous window to each window, that is, samples that belong to the previous regime by construction. In the reversed orientation this smoothed the chain; in the correct one it contaminates every fit. No bootstrap threshold recovers it: lowering the threshold trades precision for recall monotonically and nothing approaches the plain per-window fit.

5 · CausalMorph on this benchmark

To separate design from a residual defect, one stationary experiment: a linear SEM with Laplace noise, p = 6, n = 1500, density 0.3, eight seeds. This is LiNGAM's own model.

precisionrecall
DirectLiNGAM raw1.0001.000

DirectLiNGAM ∘ CausalMorph, prior = truth untransposed (the October path)0.0300.036
DirectLiNGAM ∘ CausalMorph, prior = empty1.0001.000

With the true graph as prior, CausalMorph's transform turns a perfect recovery into about 85%; with an empty prior it is the identity. The chain prior re-applies that loss window after window, which is the whole gap between the pipeline and DirectLiNGAM on the same windows. This is consistent with what CausalMorph is for: preconditioning data that violate LiNGAM's assumptions (nonlinear mechanisms, Gaussian-leaning noise). This grid is linear with Laplace innovations, where a preconditioner has nothing to fix and can only remove signal.

Defensible claims after this audit. The segmentation is the contribution, and it is now strong. On this grid the best extraction is LiNGAM per window without CausalMorph. CausalMorph's value has to be shown on a grid that violates the assumptions it was built for, which is a benchmark-design decision rather than a tuning problem.

6 · What this means for the paper

  1. Every structure number computed before the fix, including the 180-scenario subset, the report's Table 3 and the baseline win-rates, must be recomputed; the detection numbers (v1G vs v1H) are unaffected.
  2. The detection section can be written now from the validation sample and then confirmed on the full 18,000-scenario grid; detection-only runs take under an hour at 12 workers.
  3. The extraction section should compare the segmentation + per-window learner against (a) one graph fitted to the whole series and (b) CD-NOD, both correctly scored. The whole-series control is on this page's final rows.
  4. A second benchmark with nonlinear mechanisms and Gaussian noise is needed before any claim about CausalMorph inside the pipeline.
  5. The nonstationary structure-over-time metrics need one more change: transition_shd is minimised by predicting no change (a missed transition is charged only the sparse true change set); transition_f1, the edge-set F1 of learned changes, replaces it.
